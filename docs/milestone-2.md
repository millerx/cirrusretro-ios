# Native NSF playback

Cirrus Retro targets iOS/iPadOS 16 and later. Import a raw base-APU NSF through Files, choose a track and press Play. Pause retains the position. Stop restarts the selected track on the next Play. Changing tracks during playback starts the new track. The app keeps one validated file in Application Support and restores it on launch. A failed replacement preserves the previous local copy. Files provider access is security-scoped, coordinated and size-limited while reading. The metadata decoder tries UTF-8 then Latin-1.

## Audio ownership and cancellation

One serial dispatch queue owns the opaque handle from open through close, the AVAudioEngine graph and the producer timer. A Files provider can block independently of this queue. Each timer event renders at most one 512-frame block of 44.1 kHz, interleaved signed 16-bit stereo. Pending timer ticks coalesce. Stop and track changes queue behind a single active render. The C API disables GME's initial silence search. Its CPU runner already uses bounded emulated clock slices. A hash-guarded patch now rejects more than 8,192 CPU dispatches within one internal emulation quantum (about 50 ms of emulated audio). This catches pathological guest scheduling even for small PCM requests. A rejected block never enters the ring. Some syntactically valid files with extreme timing may therefore fail playback.

The single-producer/single-consumer ring holds 2,048 stereo frames (46.4 ms). Acquire/release indices publish samples and reclaim slots. The source node reads only available frames, converts to planar float, and zero-fills any shortfall. Its render block retains its storage when the graph is built. Playback never resets a live ring. Stop or reselection discards the entire graph, while pause keeps the queue and unread PCM. The mixer converts the source format for the current output route. Backgrounding pauses playback. Full interruption, route and background controls belong to Milestone 3.

Linux Release passed all five CTest entries, including the four Milestone 1 regressions. The new test exercises counter wrap, full/partial reads, stereo conversion and silence. With a synthetic 1 µs guest play period, the first 512-frame request returned a controlled error in 0.289 ms in one Linux x86-64 run. This measures a work-limit case, not an iOS scheduling deadline. Hosted XCTest also times guest rejection on ARM64 and waits for the live producer to refill beyond the ring capacity. It checks actual AVAudioEngine start/pause/resume/stop, track changes, malformed replacement, size bounds, a guest warning, and two pitches and underrun silence through the source node in offline rendering mode. See the PR check results for execution status. Device latency, battery, output routing and listening quality require owner hardware.

## Personal installation and renewal

For an owner with no development Mac, the most practical path is a private **owner-only internal TestFlight group**. The owner registered the bundle ID and created the matching App Store Connect record. Archive a reviewed revision on hosted macOS, sign for App Store Connect, upload a uniquely numbered build, add it to the internal group after processing, and install through TestFlight on the owner’s iPhone. Keep the bundle ID stable across updates. The protected GitHub Actions job below uses the existing hosted development path. Apple's initial Xcode Cloud onboarding requires Xcode. Keep signing material private, scoped to that trusted job, and outside pull-request workflows. Each TestFlight build expires after 90 days. Upload and install a replacement in advance (for example every 60 days), renew the membership annually, and monitor certificate/profile expirations. The first signed upload requires owner-provided credentials. ## Deliver the authorized owner-only TestFlight build

The registered bundle ID is `org.cirrusretro.player`. Prepare an internal group named **Owner** in App Store Connect → Apps → Cirrus Retro → TestFlight → Internal Testing. Add only the owner's Apple Account. Before approving each upload, inspect every internal group, including the default group. Every group that automatically receives this build must have only the owner as a tester or have automatic delivery disabled. If you cannot establish this for all receiving groups, stop before upload. Assign the processed build manually only to **Owner**. [Apple internal tester groups](https://developer.apple.com/help/app-store-connect/test-a-beta-version/add-internal-testers/)

**One-time GitHub setup.** In repository Settings → Environments create `owner-testflight`. Set the owner as the **sole required reviewer**. Clear **Allow administrators to bypass configured protection rules**. Leave **Prevent self-review** unchecked so the sole reviewer can approve their own deployment. Under Deployment branches and tags choose **Selected branches and tags**, add a **tag** rule `owner-testflight-*`, and allow no branches. Complete these protections before adding credentials. [GitHub deployment environment settings](https://docs.github.com/en/actions/how-tos/deploy/configure-and-manage-deployments/manage-environments)

**Apple upload key.** In App Store Connect → Users and Access → Integrations → App Store Connect API, generate the **Cirrus Retro TestFlight** Team Key with the **Developer** role. Apple grants that role across the team’s apps, including for a key named for a single project. Download its `.p8` file and record the Key ID and Issuer ID. Keep a private recovery copy. Xcode uses this key for upload authentication. The owner supplies the signing identity and profile separately. [Apple API keys](https://developer.apple.com/documentation/appstoreconnectapi/creating-api-keys-for-app-store-connect-api)

**Manual signing identity.** Reuse a valid **Apple Distribution** identity if the owner has its private key. To create one, use a trusted computer. On macOS, use Keychain Access → Certificate Assistant → Request a Certificate From a Certificate Authority, enter your email and a descriptive common name, and select **Saved to disk**. Upload the resulting CSR in Apple Developer → Certificates → **+** → **Apple Distribution**. Download and open the issued certificate on that same computer. Under Keychain Access → My Certificates, expand the certificate to verify its private key, select the identity and export a password-protected `.p12`. Store that password privately. If the team has reached its certificate limit, identify an existing usable identity before considering revocation. [Apple CSR instructions](https://developer.apple.com/help/account/certificates/create-a-certificate-signing-request/) · [Certificate management](https://developer.apple.com/help/account/certificates/certificates-overview/)

A Mac and Xcode are optional for this credential step. With OpenSSL on a trusted computer, create a new private directory outside the repository, then run the commands below there. The first two commands create an encrypted RSA key and CSR and prompt for the passphrase and subject. Upload only `distribution.csr` to the Apple Distribution form. After downloading the issued certificate as `distribution.cer`, the last two commands package it with the original key for the runner.

```sh
umask 077
openssl genrsa -aes256 -out distribution.key 2048
openssl req -new -sha256 -key distribution.key -out distribution.csr
openssl x509 -inform DER -in distribution.cer -out distribution.pem
openssl pkcs12 -export -inkey distribution.key -in distribution.pem -out distribution.p12 \
  -keypbe PBE-SHA1-3DES -certpbe PBE-SHA1-3DES -macalg sha1
```

**Provisioning profile.** In Apple Developer → Profiles → **+**, choose **App Store Connect** under Distribution. Select the explicit App ID for `org.cirrusretro.player`, choose the exact Apple Distribution certificate above, name the profile **Cirrus Retro App Store**, generate and download the `.mobileprovision` file. Record the profile and certificate expiry dates. [Apple profile instructions](https://developer.apple.com/help/account/provisioning-profiles/create-an-app-store-provisioning-profile/)

In that protected **GitHub environment**, add the following values directly from the owner's browser. Do this outside the repository-wide Actions secrets page.

| Type | Name | Value |
| --- | --- | --- |
| Environment secret | `ASC_PRIVATE_KEY` | Entire downloaded .p8 text with its BEGIN and END lines |
| Environment secret | `DISTRIBUTION_P12_BASE64` | Base64 of the exported binary .p12 |
| Environment secret | `DISTRIBUTION_P12_PASSWORD` | Its export password |
| Environment secret | `APP_STORE_PROFILE_BASE64` | Base64 of the downloaded binary .mobileprovision |
| Environment variable | `ASC_KEY_ID` | Team Key ID from Integrations |
| Environment variable | `ASC_ISSUER_ID` | Issuer ID from Integrations |
| Environment variable | `APPLE_TEAM_ID` | Team ID from Apple Developer → Membership details |

On macOS, copy a binary file as one Base64 line using `openssl base64 -A -in distribution.p12 | pbcopy`. Paste directly into the corresponding environment secret. Repeat with the downloaded profile filename for `APP_STORE_PROFILE_BASE64`. The .p8 secret uses its original text. The same OpenSSL command can feed a trusted clipboard utility on another platform. [GitHub signing secrets](https://docs.github.com/en/actions/how-tos/deploy/deploy-to-third-party-platforms/sign-xcode-applications)

**Upload.** After CI and independent review pass for the intended commit, push a new tag such as `owner-testflight-1` at that exact SHA. A tag can select the reviewed feature commit before merge. The owner compares the full 40-character deployment commit SHA on the Actions run with the approved SHA in the independent review on the PR. Approve the pending deployment only on an exact match and after checking the tester groups above. The standard macOS runner archives the device build with Xcode 27 and imports the .p12 into a temporary keychain. The delivery step checks the profile's expiry, team, app ID, and signing certificate against an installed private identity. Xcode exports with manual signing, the selected profile, `destination=upload` and `testFlightInternalTestingOnly=true`. Each new workflow run supplies its build number. Inspect App Store Connect before retrying an interrupted upload to avoid submitting an accepted build twice. [Upload SDK requirement](https://developer.apple.com/news/upcoming-requirements/?id=04282026a) · [Delivery workflow](../.github/workflows/owner-testflight.yml)

**Install.** Wait for processing. Resolve any export-compliance question in the app's TestFlight tab (the app reads local files and synthesizes audio). Verify the build is marked **Internal**, assign it to **Owner**, and install through TestFlight on the owner’s iPhone using the invited account. For a renewal, tag a reviewed commit with a new tag and install the new build before the prior one expires. Before certificate or profile expiry, export a valid matching identity and regenerate the profile, then update the protected signing secrets together. For a revoked API key, replace the protected key and key ID. Record device listening results on the PR.
