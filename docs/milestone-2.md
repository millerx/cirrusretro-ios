# Native NSF playback

Cirrus Retro targets iOS/iPadOS 16 and later. Import a raw base-APU NSF through Files, choose a track and press Play. Pause retains the position. Stop restarts the selected track on the next Play. Changing tracks during playback starts the new track. The app keeps one validated file in Application Support and restores it on launch. A failed replacement preserves the previous local copy. Files provider access is security-scoped, coordinated and size-limited while reading. The metadata decoder tries UTF-8 then Latin-1.

## Build and verify remotely

The Native iOS PR job uses a standard macOS ARM64 runner in this public repository. Device compilation is unsigned. Simulator XCTest uses the app as its host and generated music from the [Milestone 1 fixture](../tests/fixture.py). Apple enrollment and signing secrets are unnecessary for this job. The separate Portable NSF workflow retains Release and sanitizer coverage. [Runner billing and hardware](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)

On the hosted Mac, `scripts/build-ios-core` builds the exact GME revision and patched translation unit from the portable CMake build twice. It combines the C adapter and GME archives into a static library under each SDK name. The checked-in Xcode project selects by platform. Keep the device and simulator ARM64 archives separate. The script also generates the test bundle's two fixture inputs. The build, simulator selection and test commands are in the [native workflow](../.github/workflows/ios.yml).

## Audio ownership and cancellation

One serial dispatch queue owns the opaque handle from open through close, the AVAudioEngine graph and the producer timer. A Files provider can block independently of this queue. Each timer event renders at most one 512-frame block of 44.1 kHz, interleaved signed 16-bit stereo. Pending timer ticks coalesce. Stop and track changes queue behind a single active render. The C API disables GME's initial silence search. Its CPU runner already uses bounded emulated clock slices. A hash-guarded patch now rejects more than 8,192 CPU dispatches within one internal emulation quantum (about 50 ms of emulated audio). This catches pathological guest scheduling even for small PCM requests. A rejected block never enters the ring. Some syntactically valid files with extreme timing may therefore fail playback.

The single-producer/single-consumer ring holds 2,048 stereo frames (46.4 ms). Acquire/release indices publish samples and reclaim slots. The source node reads only available frames, converts to planar float, and zero-fills any shortfall. Its render block retains its storage when the graph is built. Playback never resets a live ring. Stop or reselection discards the entire graph, while pause keeps the queue and unread PCM. The mixer converts the source format for the current output route. Backgrounding pauses playback. Full interruption, route and background controls belong to Milestone 3.

Linux Release passed all five CTest entries, including the four Milestone 1 regressions. The new test exercises counter wrap, full/partial reads, stereo conversion and silence. With a synthetic 1 µs guest play period, the first 512-frame request returned a controlled error in 0.289 ms in one Linux x86-64 run. This measures a work-limit case, not an iOS scheduling deadline. Hosted XCTest also times guest rejection on ARM64 and waits for the live producer to refill beyond the ring capacity. It checks actual AVAudioEngine start/pause/resume/stop, track changes, malformed replacement, size bounds, a guest warning, and two pitches and underrun silence through the source node in offline rendering mode. See the PR check results for execution status. Device latency, battery, output routing and listening quality require owner hardware.

## Personal installation and renewal

For an owner with no development Mac, the most practical path is a private **owner-only internal TestFlight group**. After approval, use the owner's Developer Program team, a unique registered bundle ID and matching App Store Connect app record. Archive a reviewed revision on hosted macOS, sign for App Store Connect, upload a uniquely numbered build, add it to the internal group after processing, and install through TestFlight on both devices. Keep the bundle ID stable across updates. Prefer Xcode Cloud if the owner can complete its Xcode onboarding and confirm included usage. A protected, manually initiated hosted macOS signing job is an alternative. Keep signing material private, scoped to that trusted job, and outside pull-request workflows. Each TestFlight build expires after 90 days. Upload and install a replacement in advance (for example every 60 days), renew the membership annually, and monitor certificate/profile expirations. This is an installation plan; a signed delivery has yet to be tested. [Internal testers](https://developer.apple.com/help/app-store-connect/test-a-beta-version/add-internal-testers/) · [Program enrollment and fee](https://developer.apple.com/help/account/membership/program-enrollment/)

| Route | Installation and recurring work |
| --- | --- |
| Free Personal Team | Xcode signs for personal devices. Provisioning expires after seven days, requiring frequent reprovisioning and reinstall. This depends on access to Xcode and the device and is a poor fit for sustained remote use. [Apple account comparison](https://developer.apple.com/help/account/basics/about-your-developer-account/) |
| Paid ad hoc | Register the iPhone and iPad UDIDs, create an App ID, distribution certificate and ad hoc profile, then archive and export a signed IPA on a trusted hosted Mac. Apple documents Device Hub or Apple Configurator for installation, which needs a suitable device-installation host. Check the embedded profile's actual ExpirationDate and certificate validity. Renew, re-sign and reinstall before expiry or after a device change. [Ad hoc profile](https://developer.apple.com/help/account/provisioning-profiles/create-an-ad-hoc-provisioning-profile/) · [Registered-device installation](https://developer.apple.com/documentation/xcode/distributing-your-app-to-registered-devices/) · [Profile expiry](https://developer.apple.com/documentation/technotes/tn3125-inside-code-signing-provisioning-profiles) |

**Owner action before signing:** confirm an existing membership or authorize Apple's annual fee (US$99 or local equivalent), accept Apple's agreements, choose the delivery route and authorize the signing setup in a trusted credential store. The AI budget covers only the existing ChatGPT subscription. No signing, enrollment, beta uploads or external invitations are part of the PR. The statically linked engine retains the LGPL/MIT obligations in the [license audit](milestone-1.md). Sharing even one build with a friend requires the outstanding relinking and licensing review.

**Owner device acceptance:** install the same signed revision on iPhone and iPad. Import the generated pulse.nsf from Files, verify the default second track, compare both pitches, pause/resume, stop/restart and switch tracks while playing. Try a malformed file and reopen the app offline. Record device model, OS, build, output route and any dropouts or unexpected behavior in the PR. Keep secrets and device identifiers out of the report.
